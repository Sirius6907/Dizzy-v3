## Findings

### F-01 — P2 — Update dialog renders raw release-note markdown, unreadable on Light Clay

- Repro: launch app with an older build installed (`1.3.3`), wait for the update
  check → "UPDATE AVAILABLE" dialog.
- Expected: "What's new" shows plain sentences, readable dark text on the light card.
- Actual: body shows `**Full Changelog**: https://github.com/sirius6907/Dizzy-v3/compare/v1.3.3...v1.3.4`
  verbatim, inside a pale box with near-invisible text; "Later" is also low contrast.
- Evidence: `artifacts/audit/04-home-t15.jpg`.
- Root cause: `lib/services/updater/app_updater_service.dart` passed the raw GitHub
  release body to the dialog; `lib/widgets/updater/update_dialog.dart` hardcoded
  white/near-white ink regardless of theme.
- Fix (uncommitted): `plainReleaseNotes()` strips `**`, links and compare URLs from
  the body; dialog text/border colors now derive from `_ink` / `_inkSoft` /
  `_hairline` theme-aware values.
- Re-verify: needs a build with an older version installed.

### F-02 — P1 — Offline cold start leaves home on skeletons forever

- Repro: disable data (airplane mode / no DNS), cold start, wait 60s.
- Expected: human empty/offline state ("You're offline…"), with retry.
- Actual: skeleton cards remain indefinitely; only logcat shows socket errors.
- Evidence: `artifacts/audit/01-cold-start.jpg`, `artifacts/audit/02-home-loaded.jpg`,
  logcat `[CloudAuth] install upsert failed ... Failed host lookup`.
- Root cause: `lib/widgets/common/offline_aware_scaffold.dart` was a `StatelessWidget`
  that decided "online" once at build time from a cached flag, so a failed probe was
  never turned into the offline banner.
- Fix (uncommitted): converted to `StatefulWidget` with a real connectivity probe and
  no false-online default.
- Re-verify: pending fresh build + airplane-mode cold start.

### F-03 — P2 — Support language detection flagged English "do" as Hindi

- Repro: `SupportAgentService.detectLanguage('how do i download a movie')`.
- Expected: `en`. Actual: `hi` (`do` is in `hindiRoman`), so an English user got a
  Hinglish answer.
- Evidence: static (`lib/services/support/support_agent_service.dart`); reproduced at
  runtime before the fix.
- Root cause: ambiguous English token `do` listed as a Hindi marker.
- Fix (uncommitted): removed `'do'` from `hindiRoman`.
- Re-verify: pending fresh build.

### F-04 — Support "hi" / "video" behaviour — PASS

- Repro: open Help → Support, send `hi`, then `video`.
- Expected: greeting; then one specific clarifying question.
- Actual: greeting on "hi"; "video" → single focused clarifying question. Off-topic
  input is refused with a plain-text redirect. No markdown rendered.
- Evidence: `artifacts/audit/06`–`12`.

### F-05 — P3 — Rate limit 429 path (copy) unverified on device

- Repro: send 15 questions quickly, then 17 off-topic, then 26 rapid sends.
- Expected: calm "try again in a moment" message.
- Actual: no 429 was ever returned to this debug install, so the copy could not be
  exercised. Server config: `supabase/functions/support-answer/index.ts`
  `RATE_CAPACITY = 12`, `RATE_REFILL_PER_MIN = 6`, 429 body
  `retry_after_seconds: 30`.
- Root cause (client side): `SupportAgentService` previously collapsed a 429 into a
  generic `FunctionException`, surfacing the "ticket" fallback instead of a retry hint.
- Fix (uncommitted): `FunctionException` is caught explicitly; 429 → calm retry answer
  with `throttled` + `retryAfterSeconds` on `SupportAnswer`.
- Re-verify: BLOCKED — cannot provoke server-side throttling from a single debug
  client at this volume; needs a unit/edge test or a lowered server cap.

### F-06 — P2 — Cold start takes 10.7s to first frame on a warm emulator

- Repro: cold start, `am start -W`, count to `Displayed`.
- Actual: `Displayed com.sirius6907.dizzyv3/...: +10s675ms`; no ANR.
- Root cause: sequential `_safeInit` awaits on the main isolate before `runApp`
  (`env`, player settings, device id, cloud/identity) — cloud init is awaited even
  though it is documented as "non-blocking".
- Status: reported only, no fix applied (would risk auth/boot ordering in this pass).

### F-07 — P1 — Leaving the landscape player leaves the app in landscape

- Repro: open any title → Play → player forces landscape → press Back.
- Expected: details page returns in portrait (phone).
- Actual: app stayed in landscape; details then rendered its desktop two-column
  layout, whose 320dp hero floor exceeded the ~360dp landscape viewport, so the
  poster/hero filled the screen and the Watch button was off-screen.
- Evidence: `artifacts/audit/26-details-landscape.jpg`, `27-details-portrait.jpg`.
- Root cause: `player_screen.dart` `dispose()` only re-allowed all orientations and
  never restored `SystemUiMode`; `details_page.dart` `_isDesktop` was width-only.
- Fix (uncommitted): dispose restores `SystemUiMode.edgeToEdge` and locks
  `portraitUp` on phones (`_isPhone` captured in `didChangeDependencies`);
  `_isDesktop` now requires `width >= 800 && height >= 600`; hero height gets a
  second clamp at `0.55 * viewport height`.
- Re-verify: pending fresh build.

### F-08 — P1 — "Play Episodes" defaults to Season 0 (Specials)

### F-09 — P1 — Stream that opens with no duration never fails over (silent 0:00)

- Repro: Cops → Play Episodes → dead `.avi` direct link.
- Expected: automatic failover to the next source, or an error state.
- Actual: `0:00 / 0:00` black screen with controls forever; logcat
  `[PlayerScreen SUCCESS] Player opened media successfully` immediately followed by
  repeated `tcp: ffurl_read returned 0xffffff92`, no error UI.
- Evidence: `artifacts/audit/20-cops-player.jpg`, logcat excerpt in
  `artifacts/audit/logs-cops.txt`.
- Root cause: `player_screen_part_playback.dart` stall watchdog requires
  `_duration > Duration.zero`; a stream that reports "opened" but never produces a
  duration can never satisfy it.
- Fix (uncommitted): added a `neverStarted` rule — playing, duration still zero,
  position still zero, no buffering, stalled ≥ 20s → silent failover.
- Re-verify: pending fresh build (source was a sim-only dead link, may need a fresh
  dead link to reproduce).

## Inherited from DeepSeek (verified coherent, completed)

- **Startup bandwidth gate** (`startup_bandwidth_policy.dart`): measures
  throughput BEFORE the first open; a 4K source on a slow link is replaced by
  the highest affordable rung; Auto ladder is capped (`capAutoTarget`); HLS
  first-rendition capped via `hls-bitrate-max`.
- **Torrent warm-up v2** (`torrent_warmup_policy.dart`): ready = 2 MB or
  ≥512 KB + feeding swarm; hopeless = no active peers after 8s, frozen bytes
  9s, or under the floor at 14s. The old "ready at 0 bytes" is gone.
- **Torrent early rejection**: `streamTorrent` returns null for a starved
  swarm; metadata wait aborts at 10s with zero peers (was 45s).
- **PlaybackDurationGuard**: bogus/garbage durations (the `-1:56:19`
  negative-remaining repro) never reach the UI or the failover policy.
- **Torrent stall watchdog**: playing-but-no-byte-growth (14s, with 8s
  buffered headroom grace) → silent failover.
- **Seeder hard gate**: 0-seeder torrents are never auto-played.

## Fixed by Qoder in this pass

- **T-01 (P1) — silent hang after torrent rejection on switch ≥2**: a
  torrent rejection raised inside `_initStream` re-entered
